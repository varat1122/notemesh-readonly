# PR #82 — หน้าจอตรวจข้อเสนอแก้ไข (ต้นแบบออฟไลน์)

## ทำอะไร และมีไว้ทำไม

สมมติ AI เสนอเปลี่ยนข้อมูลใน Investment Thesis เราต้องให้เจ้าของเห็น
"ข้อมูลเดิม → ข้อมูลที่เสนอ → เหตุผล/หลักฐาน" อย่างชัดเจนก่อนตัดสินใจ

PR นี้เพิ่ม **หน้าจอสาธิตภาษาไทยที่เปิดจากไฟล์บนเครื่องโดยตรง** โดยใช้
บริษัท SYNTH และตัวเลขสมมติ ไม่ได้โหลดข้อมูลลงทุนของผู้ใช้

ขั้นตอน:
1. อ่านข้อมูลเดิมและข้อมูลที่เสนอ
2. อ่านข้อจำกัดของแหล่งข้อมูลและกดยืนยันว่าเข้าใจ
3. เลือก "ขอให้แก้ข้อเสนอ" / "ไม่เห็นชอบ" / "เห็นชอบในหลักการ"
4. เห็นสถานะภายในหน้าเท่านั้น หากแก้ checkbox หรือข้อความ สถานะ
   การเห็นชอบจะถูกยกเลิก เมื่อปิดหรือรีโหลดหน้า ข้อมูลจะหายไป

## ทดลองเปิดหน้าจอ

หลัง checkout PR นี้ บนเครื่องคอมพิวเตอร์ เปิดไฟล์:

    examples/offline-review-ui/index.html

ผ่าน Chrome, Edge หรือ Firefox โดยไม่ต้องเริ่ม NoteMesh server
หรือเชื่อมต่อเครือข่าย ไม่มีเครื่องมือสำหรับ import ข้อมูลจริงใน UI นี้

## ทำไมยังไม่เป็นการอนุมัติจริง

- ไม่มีระบบ login หรือพิสูจน์ตัวบุคคล
- ไม่มีการลงทะเบียน public key โดยเจ้าของจริง
- ไม่มีการลงนามด้วย private key จริง
- ไม่มีการบันทึกลง Vault, SQLite, Railway หรือ audit journal
- ไม่สร้าง signed consent, owner approval, file patch หรือ authorization
- ไม่มี frontend-to-backend network API, telemetry, storage หรือ cookie
- ไม่มีการใช้ข้อมูลบริษัทจริงในตัวอย่างนี้
- การกด "เห็นชอบในหลักการ" ไม่มีผลอื่นนอกจากเปลี่ยนข้อความบนหน้า

**ความปลอดภัย:** ตัวอย่างนี้อยู่ใน examples/ ไม่ใช่ public/ หรือ
src/routes/ จึงไม่มีหน้าจอใหม่ใน Production และไม่ได้เปิด MCP endpoint

## การตรวจสอบ

- Browser E2E เปิด HTML local file โดยตรง
- ตรวจปุ่มเห็นชอบถูกปิดจนกว่าจะรับทราบครบและพิมพ์คำยืนยัน
- ตรวจว่าเปลี่ยนเงื่อนไขแล้วสถานะเดิมถูกรีเซ็ต
- ตรวจการขอแก้ไข / ไม่เห็นชอบ / Reset และไม่หลอกว่าอนุมัติจริง
- ตรวจว่าไม่มี HTTP request
- ตรวจรีโหลดแล้วผลตัดสินใจไม่ค้าง

การต่อใช้งานกับโน้ตจริงในอนาคตต้องให้ฝั่งเซิร์ฟเวอร์ตรวจ hash ของ
snapshot, source evidence, identity, trusted key registry และ owner
authorization ใหม่ก่อนดำเนินการทุกครั้ง ไม่ใช้ checkbox ของหน้าเว็บ
เป็นหลักฐานอนุมัติ
