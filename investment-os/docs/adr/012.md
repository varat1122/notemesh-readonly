# ADR 012: Bounded synthetic capture, immutable originals and resumable registration

Date: 2026-10-22

Status: **Accepted — isolated synthetic development only. Production authentication, retention and security release approval remain open.**

## Context and choice

The registry can persist metadata but cannot prove an original document exists. Add a local synthetic capture library before implementing extraction/reconciliation. No upload HTTP route is opened and the API retains its SELECT-only database identity. Only the explicit dummy researcher/owner principals and synthetic/internal/local-research contracts are accepted. This is an operator-run test harness: a caller's synthetic label is not proof of real-data entitlement.

Use pypdf 6.21.2, openpyxl 3.1.5 and defusedxml 0.7.1, pinned by uv.lock, to inspect actual PDF/OOXML structures. These add format support without changing the preferred architecture or introducing a provider. Python stdlib handles CSV and ZIP framing. They do not render content, execute formulas or macros, or fetch URLs. No malware-free guarantee is claimed.

## Storage ownership and safety

The configured synthetic object root must be new or already carry the exact synthetic marker; existing directories are never adopted or reset. POSIX directory descriptors plus O_NOFOLLOW cover every ancestor, child directory and opened file. Store directories are owner-only. Original blobs and checksum-enveloped journal checkpoints are created with atomic link-if-absent, fsync and readback, without replacing existing bytes. The trusted local operator owns the root; these controls do not defend against a malicious administrator.

Quarantine is physically separate from accepted object names. Accepted objects are hardlinks to the exact staged inode within one filesystem, preserving original bytes without a second byte copy. Different capture requests with the same digest share bytes but retain separate Source/Document capture metadata: physical dedup is not semantic source/event reconciliation or independent corroboration. No original is opened in an office application or browser.

## Limits and format policy

Policy `synthetic-static-files-v1`: input 1,000,000 bytes, nonempty; basename-only .pdf/.csv/.xlsx suffix; UTF-8 CSV (optional BOM), rectangular rows, at most 10,000 rows/100 columns/10,000 characters per cell, formula-like cells rejected (plain negative numbers accepted).

XLSX is restricted to static worksheet/style/shared-string/theme/core metadata parts. ZIP limits: 100 entries, no duplicates/traversal/symlink/encryption/unknown compression, 1 MB per entry, 4 MB expanded total, ratio at most 100. DTD/entities/external XML resolution are disabled. Macros, external relationships, embedded objects, formulas/defined names/conditional formatting are rejected. At most 10 sheets, 10,000 rows/100 columns and 50,000 visited cells total. Many legitimate complex spreadsheets will intentionally be quarantined until explicitly supported.

PDF accepts the static PDF 1.0–1.7 subset, strict parse and terminal EOF; encrypted files, annotations/actions/JavaScript/URLs/embedded/external files/forms/rich media are rejected. All xref objects, including unreferenced objects, are inspected with limits of 5,000 objects, 50,000 graph visits, depth 50 and 100 pages. This is not complete page-stream/render validation. PDF 2.0, scanned-text OCR and rich forms are not supported.

Inspection runs in a fresh child process with no inherited credentials/config selectors, 512 MiB address space, four CPU seconds, eight-second wall timeout, no file output and 64 descriptors. It has no network-fetch code. Resource limits are defense in depth, not an OS network sandbox or antivirus. Unsupported platforms fail closed; only Linux/POSIX is validated.

## Cross-store state and failure recovery

Actor + idempotency key maps to a lock and immutable journal stages:

1. `prepared`: request fingerprint, receipt/import timestamps, original digest/size, deterministic IDs, policy version.
2. Quarantine bytes are durably stored and read back.
3. `rejected`: bounded reason code, no registry mutation; or `validated`: format-policy result.
4. Promote immutable bytes; register Document and Source through the existing repository, each with its own actor-bound key.
5. Read original bytes and both registered version-one payloads back; only then create `committed` and return `captured`.

There is no filesystem/PostgreSQL atomic transaction. A crash may leave an orphan blob or only the Document committed. Failure is reported as partial, not captured. Retry with the exact bytes and metadata resumes from checkpoints; registry replay prevents duplicate commits. A mismatched request, changed policy, corruption or missing original blocks success; originals are never silently overwritten/repaired. Interrupted temporary files and rejected originals remain for explicit reconciliation/retention work; no automatic deletion/reset exists.

Source received_at is supplied by the fixture and cannot be in the future; imported_at is captured once in the prepared checkpoint. Unknown event/published/as-of dates remain null. Capture does not mark a source verified, create Claims/Evidence, extract text, infer a company/ticker or approve model export.

## Remaining gates

Real principal/grant/revocation enforcement, production DML roles, retention/quota/antivirus policy, supervised parser hardening, coordinated object+DB backup, signed remote audit and actual source licensing precede real data/public uploads. Local workspace artifacts alone are not an independent backup. The existing PostgreSQL restore drill does not certify object recovery. No ledger, paid inference, real Vault, production deployment or broker is involved.
