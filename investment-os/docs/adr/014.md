# ADR 014: Plain-text originals and unverified paragraph review

Date: 2026-10-23

Status: **Accepted — synthetic local development only. Production source grants, approval authority, hosted cost and security release remain unapproved.**

## Problem and decision

A pasted investment-news passage mixes measurements, comparison periods and editorial conclusions. The foundation previously accepted only PDF/CSV/XLSX. Add `.txt` to the synthetic capture contract, preserving the exact original bytes and registering unverified Document/Source metadata through the existing capture saga. Add a separate derived paragraph queue and an offline Thai review-document renderer. No new dependency, model call, HTTP write route, database migration, storage owner or real Vault write is introduced.

Capture policy is selected per extension. Existing PDF/CSV/XLSX captures retain `synthetic-static-files-v1`; text uses `synthetic-plain-text-v1`. The old parser profile and artifact schemas are unchanged. The previous extractor still accepts its original three formats only. Existing captures/checkpoints are not reset, copied, relabeled or silently adopted. The broader input contract is an additive `.txt` extension; the stricter text budgets are format-specific.

## Exactness and limits

Accept strict UTF-8, at most 120,000 bytes, 200 nonempty paragraphs, 10,000 Unicode characters per paragraph. Reject binary/control characters, bidi overrides/isolates and blank inputs. Preserve BOM, Unicode combining characters, CRLF/CR/LF, tabs, spacing and original numerical lexemes. Blank lines delimit paragraphs; a wrapped single newline is retained inside a paragraph. No language-dependent sentence segmentation or semantic inference is claimed. Empty separators remain in the stored original and HTML, not as empty review candidates. Over-budget input is rejected in full, not truncated.

Text admission uses bounded built-in decoding/regex in the caller process; it is not a rich-format parser and does not invoke interpreters, resolve URLs or read embedded resources. Hidden controls are rejected for readability, not as a substitute for the future prompt-injection threat model.

`TextReviewItem` has deterministic UUID, exact excerpt SHA-256, zero-based end-exclusive Unicode offsets, one-based physical lines and a mechanical `contains_number` flag. This flag means a decimal digit occurs, not that the item is a factual/numerical claim. Every item is `needs_human_review`, `untrusted_data=true`, `independent_evidence=false`. A paragraph may contain several claims or a mixture of fact and opinion; human atomic-claim review remains future work.

`TextReviewPacket` binds source/document IDs and explicitly selected revisions, both metadata digests, original byte hash, algorithm `synthetic-paragraph-review-v1`, item IDs and full output digest. Deterministic output excludes wall-clock creation metadata. An immutable journal envelope separately records creator/time. Outputs are capped at 500,000 canonical JSON bytes; the offline HTML is capped at 900,000 bytes. Algorithm/segmentation changes require a version bump.

## Authority, verification and rendering

Only existing exact dummy researcher/owner principals can capture or create drafts. A dummy reader can verify citations. Every draft operation reloads registry records and reopens original bytes, then recomputes the complete packet, including on cache replay. Citation verification likewise checks the entire packet against originals before returning an item. Self-consistent forged IDs/hashes cannot certify a substituted excerpt. Concurrent generation uses the store's per-key lock and immutable checkpoint; failure preserves source bytes and registry records for an exact retry. No Claim/Evidence record is created or promoted by this operation.

The HTML is a static local walkthrough tailored to the fictional AI-spending fixture. Every untrusted character is escaped; only generated fragment links are clickable. A restrictive CSP denies remote resources/scripts/forms and permits only the hash of the embedded static style. No JavaScript, save button, remote font or public server is required. The renderer checks all paragraph coverage/offsets against supplied original bytes; DB-backed identity verification is performed by the service/demo before rendering, not asserted by a standalone HTML file. Browser display may normalize line endings visually; authoritative offsets refer to the decoded original, not DOM text or byte positions.

Questions about source/year, sample coverage, spending versus volume/price, percentage points and denominator differences are a visible review checklist, not automated findings. Unknown publication/event/as-of dates remain null in the original registry. Import time never supplies a missing reporting year.

## Deferred work

Real local identity/grants and source licensing, reviewed atomic claims, original publisher/report association, semantic duplicate/correction resolution, independent evidence collection, financial normalization, protected approval receipts and coordinated object+DB backup are still required. The marked object directory is workspace-local storage, not an independent backup. No spending/evaluation ledger is read, created, reset or copied by this milestone.
