# ADR 004: Modular monolith and Python layout

Date: 2026-10-22

Status: **Accepted — P0 implementation**

## Context

The system has many conceptual desks but no evidence that each needs an independently deployed service.

## Decision

Use one installable src/investment_os package with domain, ports, policy, adapters, storage and API modules. Future workers reuse it. Add implementations only when their phase needs them; do not create empty folders for every planned desk.

## Alternatives

The blueprint example apps/packages tree can be adopted later. Microservices now add authentication, queues, deployment and distributed consistency before the first loop works.

## Consequences and limits

Python package boundaries need tests/review; import direction must remain inward. P0 does not implement a worker or multi-agent runtime.

## Approval and migration

Extraction retains DTO/UUID contracts. Split only for demonstrated scaling, privilege isolation or release lifecycle needs; record a new ADR before changing deployment.

Evidence: Master Blueprint §§01–05, 16–18, 21–23; actual validation is recorded separately in IMPLEMENTATION_STATUS.md.
