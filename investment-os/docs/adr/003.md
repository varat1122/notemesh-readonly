# ADR 003: DuckDB and Parquet

Date: 2026-10-22

Status: **Accepted — P0 storage foundation**

## Context

Time-series and backtest tables should not bloat Markdown or become model-generated arithmetic.

## Decision

Parquet holds immutable versioned analytical artifacts. DuckDB queries them locally. PostgreSQL holds dataset manifests, provenance, rights and run references.

## Alternatives

PostgreSQL-only is viable at small scale but less portable for columnar snapshots; a cloud warehouse introduces avoidable early cost and lock-in.

## Consequences and limits

Partitions require atomic manifest publication and rights/adjustment/as-of checks. P0 proves one synthetic file roundtrip, not real market ingestion or a quant engine.

## Approval and migration

Portable Parquet and SQL preserve dataset IDs through object-store migration; partitioning/retention tuned only with measured data volume.
