# ADR 010: Versioned JSONB foundation and incremental normalization

Date: 2026-10-22

Status: **Accepted — P0 foundation; field projections Proposed for P1**

## Context

All 14 requested domains need shared contracts now, while implementing every later domain table and service would exceed P0.

## Decision

Materialize canonical identity/version/reference/operation/audit/receipt/grant tables now; store typed domain payloads as immutable JSONB validated by Pydantic. Generate JSON Schema for every entity and DTO. Expose no business-persistence API until the P1 repository enforces typed references and digest consistency.

## Alternatives

Separate typed tables for every future entity give stronger SQL domain constraints but would pre-implement unsettled workflows. A schema-less document blob with no shared registry would lose canonical referential integrity.

## Consequences and limits

JSON Schema and SQL each cover part of integrity; neither replaces the other. P1 must check target kind, materialize every reference, validate licenses and maintain projections atomically. This limitation is explicit, not claimed complete.

## Approval and migration

Add normalized domain columns/tables for actual query/invariant needs without changing UUIDs, retain versioned payload history and test backfill/read compatibility. Owner schema sign-off remains pending.

Evidence: Master Blueprint §§01–05, 16–18, 21–23; actual validation is recorded separately in IMPLEMENTATION_STATUS.md.
