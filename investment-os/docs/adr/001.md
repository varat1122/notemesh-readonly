# ADR 001: PostgreSQL canonical registry

Date: 2026-10-22

Status: **Accepted — P0 local synthetic scope**

## Context

Identities, references, evidence decisions and operation receipts need transactionality and durable constraints.

## Decision

Use PostgreSQL with UUID identities, immutable versions, FK references, actor-scoped operation keys and an append-only audit foundation. Alembic owns schema history.

## Alternatives

SQLite is simpler for one process but lacks the intended deployment/role boundary. A graph database or document DB adds operating cost before measured need.

## Consequences and limits

P1 must implement typed-reference extraction and repository transactions; SQL JSONB does not automatically validate complete domain semantics. No managed database subscription is approved.

## Approval and migration

Retain canonical IDs during later schema normalization; additive migration plus replay tests. Local SELECT-only API role tested separately from migration owner.
