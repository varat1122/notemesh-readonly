# ใช้ข้อความข่าวใน Investment OS อย่างไร

เป้าหมายคือเปลี่ยนข้อความที่อ่านเจอให้เป็นงานวิจัยที่ย้อนตรวจได้ ก่อนนำไปประกอบการตัดสินใจลงทุน

## ตัวอย่างที่ทดลองได้ตอนนี้

หลังเปิดระบบ local แล้ว รันจากโฟลเดอร์ `investment-os`:

```bash
uv run --frozen python scripts/text_review_demo.py
```

โปรแกรมจะสร้างข้อความเรื่องค่าใช้จ่าย AI ที่แต่งขึ้นทั้งหมด เก็บต้นฉบับ แยกย่อหน้าเป็นรายการรอตรวจ และแสดงตำแหน่งไฟล์ HTML ภาษาไทย เปิดไฟล์นั้นด้วย browser แล้วกด “อ่านข้อความเดิม” เพื่อย้อนกลับไปดูบริบทได้ รันซ้ำจะได้รายการและตำแหน่งเดิม

นี่เป็นเอกสารตัวอย่างในเครื่อง ยังไม่มีหน้าวางข่าวจริงหรือระบบบันทึกผลอนุมัติ ข้อมูลจำลองต้องอยู่ในพื้นที่ทดสอบ ห้ามเปลี่ยนป้ายข่าวจริงให้เป็นข้อมูลจำลองเพื่อข้ามขั้นตอนสิทธิ์

## ถ้าเจอข้อความว่า AI spending กำลังชะลอ

1. **เก็บข้อความและที่มา** — ต้องหา URL รายงานต้นฉบับ ผู้เผยแพร่ วันที่ และปีที่กล่าวถึง ข้อความที่บอกเพียง August/September ยังไม่พอระบุช่วงเวลา
2. **แตกเป็นคำถามที่ตรวจได้** — ยอดใช้จ่ายชะลอจริงไหม ราคาเฉลี่ยลดเท่าไร ปริมาณ token เพิ่มไหม และตัวเลขลูกค้ารายใหญ่ใช้ฐานเดียวกันหรือไม่
3. **อ่านนิยามก่อนเปรียบเทียบ** — spending ไม่เท่ากับจำนวน token; realized price ขึ้นกับส่วนผสมโมเดล/ประเภท token; % ไม่เท่ากับ percentage points; ลูกค้าในเครือข่ายชำระเงินหนึ่งไม่ใช่บริษัททั่วโลก
4. **หาเอกสารสนับสนุนและคัดค้าน** — เทียบรายงานต้นทาง วิธีคำนวณ กลุ่มตัวอย่าง และข้อมูลผู้ให้บริการ ห้ามนับโพสต์ที่คัดลอกจากแหล่งเดียวกันเป็นหลักฐานอิสระหลายชิ้น
5. **ค่อยประเมินผลต่อ thesis** — ผลต่อผู้ให้บริการโมเดล ผู้ใช้ AI และผู้ผลิตโครงสร้างพื้นฐานอาจต่างกัน รายได้ชะลอเพราะราคาลดไม่ได้ยืนยันว่าความต้องการประมวลผลลดลง
6. **ให้คนตัดสินก่อนเปลี่ยนข้อสรุปลงทุน** — ผลลัพธ์ที่เหมาะสมอาจเป็น “ควรติดตาม/ยังสรุปไม่ได้” ไม่จำเป็นต้องรีบซื้อหรือขาย

## ระบบทำอะไรให้แล้ว และอะไรยังต้องทำต่อ

| ขั้น | ปัจจุบัน |
|---|---|
| เก็บต้นฉบับพร้อมรหัสและตรวจว่าอ่านกลับได้ตรงเดิม | ทำได้กับข้อมูลจำลอง |
| แบ่งย่อหน้าและลิงก์กลับต้นฉบับ | ทำได้กับข้อมูลจำลอง |
| ตรวจว่ามีตัวเลขอยู่ในย่อหน้า | ทำได้ เป็นเพียงตัวช่วยจัดรายการ |
| แยกข้อกล่าวอ้างย่อยและข้อเท็จจริงออกจากความเห็น | ยังต้องมีคนทบทวน |
| ตรวจข่าวกับแหล่งอ้างอิงจริง | ยังไม่ได้เชื่อมในระบบนี้ |
| บันทึกผลอนุมัติและแก้ Current Thesis | ยังไม่เปิดใช้งาน |

งานวิศวกรรมถัดไปคือสร้างข้อเสนอ Claim/Evidence ที่ตรวจย้อนกลับได้ พร้อมขั้นตอนให้คนยอมรับ/ปฏิเสธหรือระบุว่าเป็นข่าวซ้ำ/ข่าวแก้ไข ก่อนเปิดรับข้อมูลจริง ต้องทำสิทธิ์เข้าถึงและเงื่อนไขแหล่งข้อมูลให้ครบด้วย
